# Improving pebbl init

Written 2026-10-27 from reading `src/init.js`, `src/handoff.js`, `src/context.js`, and the pebbl stores in `13 proxy-magic` and `36 Mobile-Home-Parks`.

## What the two repos show

| | Proxy Magic | Mobile-Home-Parks |
|---|---|---|
| Entries | 136 events: 78 decision, 31 quality, 13 uncategorized | smaller, tagged by park |
| Handoffs | 3 in a week that merged 19+ PRs | 4 in one day |
| Open handoffs | #3, two days old, todo already stale | all 4 open, none ever closed |
| Handoffs linking a doc | 0 (yet `docs/handoffs/headless-and-art-pipeline.md` exists) | 0 (on purpose, CLAUDE.md says `--no-doc`) |
| Narrative | empty | set |
| CLAUDE.md mentions pebbl | no | yes, with its own logging rules |
| Session-end check | none | `bin/pebbl-check` Stop hook |

Proxy Magic logs decisions well because the agent sees AGENTS.md, but nothing makes it write a handoff, so most sessions end without one. Mobile-Home-Parks writes a handoff every session because its Stop hook asks, but nothing closes the old ones, so they pile up as "open". Both problems sit in what init sets up.

## Suggestions, most impact first

### 1. Ship the session-end check with init

Mobile-Home-Parks' Stop hook is the reason its handoffs exist. Make it a pebbl command and have init wire it up.

- Add `pebbl check-session` (reads the Claude Code hook JSON on stdin). It blocks once when files changed or commits landed since the session started and there's no log entry or handoff since then. Same logic as `bin/pebbl-check`, minus the repo-specific part.
- The repo-specific "decision N in 10.01 has no entry" check becomes config, not code:
  ```yaml
  # .pebbl/config.yml
  session_check:
    decisions_file: docs/10.01 Decisions.md
    decision_pattern: '^(\d+)\.\s'
  ```
- `pebbl init` writes the Stop hook into `.claude/settings.json` (merging, never clobbering existing hooks, as Mobile-Home-Parks already has `park-check`). `--no-claude-hooks` skips it.
- Make "ended without a handoff" its own reason in the block message, so the agent writes one even when it already logged entries.

### 2. A new handoff replaces the previous open one

`handoff.js` says it outright: "creating a handoff never closes priors, so opens stack silently". The nudge to run `--close N` gets ignored every time (Mobile-Home-Parks: 4 of 4 open).

- When a new handoff is created, close the earlier open handoffs on the same topic (or all of them when no topic is given) and carry their unfinished todos forward, prefixed `carried from #N:`. The agent then decides in one place what's still real.
- `--keep-open` for the rare case of two parallel threads.
- `pebbl context` already warns about stacked opens. Once this lands, that warning should be rare enough to mean something.

### 3. Let the repo choose its handoff style in config, not by fighting AGENTS.md

Mobile-Home-Parks had to write "This overrides the detail-heavy handoff paragraph in AGENTS.md" into CLAUDE.md. A repo shouldn't have to argue with its own generated block.

```yaml
handoff:
  docs: when-heavy    # when-heavy (today) | never | always
  docs_dir: docs/handoffs   # Mobile-Home-Parks would set docs/13 handoffs
```

The AGENTS.md block is rendered from these values, so it says the right thing for each repo. `docs: never` also turns off the 1200-char refusal.

Proxy Magic's orphaned handoff doc points at a second gap: the detail-doc guard only fires on long handoffs. If a file under `docs_dir` was added or changed this session and the handoff links nothing, `pebbl handoff` should say "you wrote X, link it with --docs".

### 4. Make Claude Code actually read the guidance

init writes only AGENTS.md. Proxy Magic's CLAUDE.md never mentions pebbl, so the instructions depend on the agent happening to open AGENTS.md. When a CLAUDE.md exists, init should add one line near the top:

```
@AGENTS.md
```

(or a one-sentence pointer: "Run `pebbl context` before anything else; AGENTS.md says how to log.") Mobile-Home-Parks does this by hand in its line 3.

### 5. Rewrite the default AGENTS.md block around Mobile-Home-Parks' rule

The Mobile-Home-Parks rule works better than the stock text: "pebbl is an index, not a place for documents. Log one line right then: what, why, and where the detail lives." Fold that into the default block, and:

- Drop the bcrypt/argon2 example; use a neutral one that shows the "where it lives" pointer, e.g. `... because X (see docs/12.03, PR 41)`.
- Say which `--cat` to use for what in one line each (decision, steering for dead ends, integration for outside systems, structure for where files live). Proxy Magic's 13 uncategorized entries suggest agents don't know.
- Keep it under ~15 lines. The current block spends a whole paragraph explaining the detail-doc refusal.

### 6. Fix `;` splitting inside parentheses

Proxy Magic handoff #2 has `done: OpenAI key fixed (set-key` and `done: the 401 was security's 128-char prompt cut)` as two broken items. `splitItems` should split only on top-level `;` (not inside `()`, `[]` or quotes), or accept `--done` repeated once per item.

### 7. Don't let init finish without a narrative

Proxy Magic's `.pebbl/narrative.md` is still the empty placeholder. Options, cheapest first:

- init seeds the narrative from the first paragraph of README.md and prints it for the agent to correct.
- `pebbl context` prints a one-line warning while the narrative is empty.
- `check-session` (suggestion 1) blocks once on an empty narrative.

### 8. One pebbl install, and hooks that run the right Node

- The git hooks in both repos are pinned to `~/factory/pebbl/bin/pebbl.js`, while the checkout you work on is `34 pebbl`. They're in sync now (the 14 newer commits are memory-only), but code fixes landed in one won't reach the hooks. Pick one: point the `~/factory/agentbox/bin/pebbl` wrapper's `PEBBL_HOME` at `34 pebbl` and re-run `pebbl upgrade` in each repo, or keep factory as the install and treat `34 pebbl` as the dev copy.
- The hooks run `node "$PINNED"` from whatever `node` is on PATH. The wrapper exists because Node 24 breaks better-sqlite3. A hook fired from a GUI app or a shell with Node 24 fails quietly. init should pin the node binary too, or call the wrapper.
- Commit capture looks thin: Mobile-Home-Parks has 6 commit events for 20 commits. Some predate init, but it's worth a `pebbl doctor` check that compares `git log` against captured commits and says why they're missing.

## Suggested order

1 and 2 fix handoffs in both repos and are the reason for this note. 3 and 4 remove the need for per-repo overrides. 5 to 8 are smaller and can ride along.

After the change, re-run `pebbl upgrade` in Proxy Magic and Mobile-Home-Parks, delete `bin/pebbl-check` from Mobile-Home-Parks in favour of the built-in check, and move its decision-file setting into `.pebbl/config.yml`.

## Review and decisions (2026-10-27)

An independent Fable reviewer checked each suggestion against the code and both stores. Two of my claims were wrong: Proxy Magic's three handoffs all link a doc (`handoffs.md` just doesn't render the docs field), and Mobile-Home-Parks has no pebbl git hooks at all since it was re-cloned into `36 Mobile-Home-Parks` (the pinned hooks are still in the old `~/work` clone). It also found a gap the proposal missed: handoff create and close never write events, so a shared or events-mode store loses every handoff on rebuild.

| # | Decided |
|---|---|
| 1 | Build `pebbl check-session`; init and upgrade add it to `.claude/settings.json` as a Stop hook. Stop fires every turn, so it blocks when the newest local change (a commit since the session started, or a dirty file modified since then, outside `.pebbl/`) is newer than the newest agent-written pebbl entry or handoff. Commit captures from the git hook don't count as logging. The decisions-file check comes from `session_check:` in config.yml. It never exits non-zero, finds `.pebbl/` from cwd (so worktrees work), and runs through the same pinned node as the git hooks. |
| 2 | A new handoff closes every earlier open handoff, not only same-topic ones (Mobile-Home-Parks' four open handoffs have different park topics, so a same-topic rule would leave them stacked). Unfinished todos carry into the new one as `from #N: ...`, skipping any the new handoff already lists in done or todo. Auto-close demotes session entries exactly like `--close`. `--keep-open` opts out for parallel threads. |
| 3 | Build `handoff.docs` (`when-heavy`, `never`, `always`) and `handoff.docs_dir` in config.yml; the AGENTS.md block is rendered from them by init and upgrade. Drop the orphan-doc nudge: its premise was wrong. |
| 4 | init and upgrade add `@AGENTS.md` under the first heading of an existing CLAUDE.md. Never create CLAUDE.md. |
| 5 | Rewrite the block around "what, why, where the detail lives", a one-line `--cat` guide, and repeatable `--done`/`--todo`. The 13 uncategorized entries were commit captures, not agents, so that's no longer a reason. |
| 6 | Built: one paren-aware `splitItems` in `src/items.js`, used by handoff.js, view.js and context.js. |
| 7 | init seeds an empty narrative from README's first paragraph and says so. `pebbl context` already hints when it's empty; check-session won't nag about it. |
| 8 | One `pinnedNode()` helper: hooks run `realpath(process.execPath)` (fnm's per-shell node path vanishes), falling back to PATH `node`. `pebbl upgrade` reinstalls all five git hooks, not only post-commit. `pebbl doctor` reports missing or foreign hooks and commits never captured (matched on message and date, since rebases change hashes). `~/factory/pebbl` stays the install and `34 pebbl` the dev copy. |
| 9 | Handoff create and close append `handoff-open` / `handoff-close` events. A close finds its open event by timestamp and summary, so no schema change. |
